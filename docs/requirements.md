# PayBalance 要件書

## 1. 目的

PayBalance は、二人で出かけたり食事をした際の支払いを記録し、累積の立替差額から次に支払う人を示すモバイルファーストの Web アプリである。

初期版は React 製 PWA とし、Cloudflare 上で提供する。対象通貨は日本円のみとする。

## 2. 用語

- **ペア**：二人の利用者で構成する共有単位。各利用者は同時に一組のペアにのみ所属できる。
- **支出**：支払者、負担額、任意メモからなる記録。
- **差額**：二人の累積立替額の差。差額が少ない人を「次に支払う人」とする。
- **端数繰越**：一括支出が奇数円のときに発生する1円の配分状態。

## 3. 利用者・ペア

### 3.1 認証

- Google ログインを用いる。
- Google アカウントの表示名を初期の表示名とする。
- 表示名は設定ページからいつでも変更できる。
- 表示名の変更は、過去の履歴を含むすべての表示へ直ちに反映する。履歴に表示名のコピーは保存しない。
- Google ログイン用メールアドレスは相手に表示しない。

### 3.2 ペア作成と招待

- ペア作成者は相手のメールアドレスを入力して招待する。
- 作成した招待リンクを画面に表示し、OSの共有機能またはコピーで相手へ手動共有する。
- 招待を受ける利用者は、招待先と同一のメールアドレスで Google ログインしなければならない。
- 招待リンクの有効期限は7日間とする。作成者は設定ページから再発行または取り消しできる。

### 3.3 表示順

- 初期状態では、招待された人を左、ペア作成者を右に表示する。
- ペアのどちらも設定ページから左右の表示順を入れ替えられる。
- 差額が0円の場合、右側の人を「次に支払う人」とする。

### 3.4 ペア解消とアカウント削除

- ペア解消時は、累積値、履歴、端数繰越を含む共有データを全削除する。元のペアを復元する機能は持たない。
- 解消後、各利用者は別の相手と新しいペアを作成または参加できる。
- アカウント削除時は、本人のプロフィールと所属ペアの共有データを全削除する。
- 精算リセット、ペア解消、アカウント削除は、一方が申請し、もう一方がアプリ内で承認した時点で実行する。
- 承認待ち申請は7日間で失効し、承認前は申請者が取り消せる。

## 4. 支出の登録と計算

### 4.1 登録項目

- 支払者：二人のいずれか。初期値は「次に支払う人」とする。
- 負担方式：`個別` または `一括`。初期値は `個別` とする。
- 金額：1円以上の整数のみ。
- 用途メモ：任意。`個別`では左右それぞれに、`一括`では支出全体に入力できる。
- 日付、カテゴリ、通貨選択は設けない。

### 4.2 負担方式

- `個別`：二人それぞれの負担額を入力する。空欄は0円として扱う。二人とも0円となる記録は保存できない。
- `一括`：合計額を二人で等分する。
  - 偶数額は等額に配分する。
  - 奇数額は、支払っていない側の負担を1円多くする。たとえば累積差額が0円の状態でAが2,001円を支払った場合、次に支払う人はB、差額は1,001円となる。
  - 奇数額で1円多く負担した人を端数繰越として保持する。次の奇数一括支出では、支払者にかかわらず前回とは反対の人へ1円を多く配分する。奇数一括支出が2回あれば、二人の合計負担は厳密に1:1となる。

### 4.3 残高表示

- 各人について、支出ごとの「実際に支払った額 − 負担額」を累積する。
- 累積立替が少ない人を「次に支払う人」として表示する。
- 差額が0円の場合は、表示順で右側の人を「次に支払う人」とする。

## 5. 履歴と精算

- 履歴明細は最新10件だけを保持し、新しい順に表示する。
- 11件目以降は、支払者・金額・メモなどの明細を自動削除する。ただし残高計算に必要な累積値と端数繰越は保持する。
- 履歴は左右二列で表示し、各人の負担額と任意メモを対応する列に示す。負担方式は表示しない。
- 履歴行をタップすると編集でき、左方向へスワイプすると削除操作を表示する。
- ペアのどちらも、最新10件の履歴を編集・削除できる。変更後は、保持している累積値・履歴・端数繰越から残高を再計算する。
- 実際に精算したときは、設定ページから精算リセットを申請できる。承認されると残高を0円にし、履歴と端数繰越を全削除する。
- 同じ履歴が同時編集された場合は、先に保存された変更を採用する。後から保存しようとした利用者には更新済みであることを表示し、再読み込み後の再編集を求める。

## 6. PWA と同期

- オフライン時も新規支出は端末内に保留して追加できる。
- 保留中の支出には「同期待ち」を表示する。
- 通信復帰後、支出はサーバーの受付順に確定する。この順序を履歴順および端数繰越の計算に用いる。
- 同期失敗時は端末内の記録を残し、エラーを表示する。利用者は再試行または削除を選べる。
- オフラインでの編集・削除は対象外とする。
- プッシュ通知は実装しない。相手の変更はアプリを開いたときに最新状態として確認する。

## 7. UI 方針

- UIは Figma ファイルの `PayBalance` ページのみを参照する。`household` ページは参照しない。
- Figma に定義されたカラーコードを用いる。レイアウトは操作性と視認性を優先し、必要に応じて調整してよい。
- 表示名、表示順、招待管理、精算リセット、ペア解消、アカウント削除は、日常入力から分離した設定ページに置く。

## 8. 初期版の対象外

- 複数ペアへの同時所属
- 支出カテゴリ、家計簿・予算機能、集計グラフ
- 日付入力・日付表示
- 通貨切替
- アバター選択・画像アップロード
- プッシュ通知
- 元のペアの復元
